## 状況

プライベートベータ 2、2026 年 9 月 24 日リリース。原則は安定しており、プラットフォームに関する結論は Antigravity デスクトップ 2.17.0 と agy CLI 1.2.9 で検証し直しています。テストが変更を求めれば、スキルは今も変わります。固定の版が必要ならコミットを指定し、更新の前に [CHANGELOG.md](CHANGELOG.md) を読んでください。

## なぜ必要か

どの分野でも、質の悪いエージェントの出力の大半は三つの失敗から来ます。

| 失敗 | 現れ方 | Gravitas がすること |
| :--- | :--- | :--- |
| もっともらしい不完全さ | エージェントが問題の一部を調べ、何か本物を見つけて止まる。発見は正しく、網羅はそうではない。 | ファンアウトの前に作業リストを見つけ、報告の前に網羅性の批評を走らせる |
| 合意による幻覚 | 複数のエージェントが同じ資料を読み、同じ誤った結論に至る。誤りが相関しているから。 | すべての主張をその裏にある独立した検証で層に分け、同意を証拠として数えない |
| 機械的な調子 | 仕事は正しいのに生成されたものに読め、誰かが確かめる前に捨てられる。 | すべての成果物を `slopcheck.py` が測る文章の基準に合わせる |

これはコーディング専用のスキルではありません。同じ規律が法律、数学、物理、医学、統計、歴史、そして日常の事実の問いにも当てはまります。分野によって変わるのは使える独立した検証の種類であり、ほぼどの分野にも少なくともひとつはあります。

## 何をするか

| 段階 | 生み出すもの |
| :--- | :--- |
| トリアージ | 仕組みを動かす前に、些細な問いにはそのまま答えるという判断 |
| タスクの記録 | 計画の前に書き出す、結果の重さ、成果物、検証できる表面、欠けている入力、使えるツール |
| 規模 | quick、standard、full、exhaustive のいずれかで、ファンアウト、票、停止の数が決まっている |
| 範囲 | 推測ではなく、実際のツールで作った作業リスト |
| ファンアウト | 項目か観点ごとに読み取り専用の専門役をひとり。絶対パスと返却スキーマを渡す |
| 検証 | すべての主張を証拠の層でできるだけ高く押し上げ、委任した主張はすべてサブエージェントのトランスクリプトと照合する |
| 批評 | 新しいエージェントが、探されなかった角度と検証されなかった主張を挙げる |
| 報告 | 深刻度順の発見に、層、欠落、上限、失敗したすべてのサブエージェントを添える |

## 証拠の層

すべての主張に層のラベルが付き、すべてのラベルがそれを生んだものを示します。

| 層 | 必ず起きていなければならないこと | 該当しないもの |
| :--- | :--- | :--- |
| `observed` | 成果物そのものを調べた | 計算。調べるものが何も渡されていないときのすべて |
| `executed` | ツールが実行されて値を返し、そのコマンドを示せる | 暗算。仮定した入力での本物の計算 |
| `read` | 出典を取得し、依拠する一行を引用できる | 知っている出典。記憶によるピンポイント引用。出典について書かれたページ |
| `inferred` | 自分の推論と、思い出したことすべて | |

`observed` は成果物を、`executed` はコマンドを示し、`read` は URL を挙げて一行を引用し、欄を埋められないラベルは `inferred` です。この規則の以前の二つの版はただの禁止で、22 件のテストケースでどちらも振る舞いを変えませんでした。ラベルに URL、コマンド、ファイル名を必ず入れさせると変わりました。実際に取得していなければ、その欄は埋められないからです。

ベータ 2 はこの欄を二か所で機械的に確かめます。ファンアウトの台帳は出所が空のレコードを格下げします。`provenance_check.py` は回答のすべてのラベルを会話のトランスクリプトと突き合わせ、URL が一度も開かれていない `read` ラベル（検索の要約から持ってきたものを含む）と、コマンドが一度も走っていない `executed` ラベルを不合格にします。

## 代理指標の罠

本当の問いは確かめにくく、隣の問いは確かめやすいとき、確かめられるのは簡単なほうです。それが通り、作業は「検証済み」と報告されます。

| 本当に重要な問い | 実際に確かめられる代理指標 |
| :--- | :--- |
| このシーンはチョコレート工場に見えるか | キャリアが 10 台、ローラーが 6 本あるか |
| この契約は私が主張する義務を生じさせるか | *indemnify* という語があるか |
| この証明は正しいか | すべての行の書式が整っているか |
| この研究は主張を裏づけるか | 引用された論文は存在するか |
| このページはアクセシブルか | Lighthouse が 100 点か |
| このプラットフォーム機能は動くか | ドキュメントに書いてあるか |

確かめ方は、本当に気にしていることが偽のときにも、その検証が通り得るかです。通り得るなら、それは代理指標です。残したうえで、隣に本当の検証を加えます。

## 検証エージェント

プラグインには八つのカスタムエージェントが同梱されています。判断する役割はどれも編集ツールを持たないので、批評役が誤診したものを修理して成功を報告することはできません。各エージェントは `inheritCustomizations: false` と `inheritMcp: false` を設定しており、ユーザーのルール、スキル、MCP サーバーをコンテキストの外に置きます。また相対パスは推測せずに拒否します。

| エージェント | 仕事 | ツール | モデル |
| :--- | :--- | :--- | :--- |
| `gravitas-scout` | ファイル、ルート、シンボル、出典の場所を探す | `list_dir`、`find_by_name`、`grep_search`、`view_file` | flash |
| `gravitas-reader` | 指定したファイルや URL について具体的な問いに答え、行を引用する | 読み取り系ツール、`read_url_content` | flash |
| `gravitas-finder` | 作業リストの上でひとつの種類の欠陥を探す | 読み取り系ツール、`read_url_content`、`search_web` | flash |
| `gravitas-checker` | 独立した検証をひとつ走らせる：計算、テスト、クエリ | `view_file`、`run_command` | flash |
| `gravitas-refuter` | ひとつの主張の反証を試み、既定で反証済みとする | 読み取り系ツール、`read_url_content`、`search_web` | pro |
| `gravitas-visual-critic` | ソースを見ていない閲覧者として取得画像を判断する | `view_file` | pro |
| `gravitas-completeness-critic` | 探されず、開かれず、走らされず、検証されなかったものを挙げる | 読み取り系ツール | pro |
| `gravitas-prose-editor` | 草稿を文章の基準に合わせて直す | `view_file` | pro |

## なぜ Antigravity 向けなのか

編成についての助言の多くは、テキストとファイルだけのツール環境を前提にしています。Antigravity の環境はもっと広く、ブラウザのスクリーンショット、コンソールの取得、ネットワークの調査、JavaScript のその場での実行、画像生成、ツールリストが固定されたカスタムエージェント、そしてスキル、エージェント、ルールをまとめて運ぶプラグインの仕組みがあります。スクリーンショットを見る批評役は、要素の重なり、切れた文字、足りないコントラスト、400 px で崩れるレイアウト、DOM にあるのに見えないコントロールを捕まえます。どれもコードを読む人には見えません。

## クイックスタート

**macOS / Linux：**

```bash
git clone https://github.com/Emily2040/gravitas.git
cd gravitas
bash scripts/install.sh ja
```

**Windows PowerShell：**

```powershell
git clone https://github.com/Emily2040/gravitas.git
cd gravitas
pwsh scripts/install.ps1 ja
```

どちらも `scripts/install.py` を実行します。リポジトリを検証し、`plugin/` を `~/.gemini/config/plugins/gravitas/` にコピーし、結果を検証します。以前スキル単体として `~/.gemini/config/skills/gravitas` に入れた版とその `gravitas-always-on` フックは、日時付きのバックアップフォルダに移されます。そのあと Antigravity を再起動するか、CLI で `/skills reload` を実行します。Python 3.8 以上が必要です。

グローバルにインストールしてください。ドキュメントが何と言っていても、CLI はワークスペースの `.agents/` フォルダを読みません（open issue #1052）。

## リポジトリの構成

```text
plugin/                                   # ~/.gemini/config/plugins/gravitas/ としてインストール
├── plugin.json                           # プラグインのマニフェスト
├── rules/AGENTS.md                       # 常時有効のルール：スキルを読み込む場面と三つの中核規則
├── agents/                               # 読み取り専用の検証エージェント 8 つ。scripts/build_agents.py が生成
└── skills/gravitas/
    ├── SKILL.md                          # ルーター（500 文字未満）。references/00-orchestrator.md を読み込む
    ├── references/                       # 00〜13 の 14 モジュール。どれも 100 行未満
    ├── schemas/                          # 発見と判定のレコード
    ├── scripts/                          # ledger.py、provenance_check.py、check_skills.py、slopcheck.py
    └── examples/gates.example.js         # もとになったシーンで赤くなるゲートスイート
locales/{zh-CN,ja,ko}/                    # 翻訳したスキルとルール
scripts/                                  # install.py とラッパー、build_agents.py
tests/audit-case/                         # 欠陥を三つ仕込んだ監査のテストケース
```

## 検証

編集のたびに検証ツールを走らせます。Antigravity は壊れたスキルを、ローテーションするログに一行残すだけで読み飛ばします。またドキュメントは、未対応のツール名がカスタムエージェントを停止させ得ると警告しています。

```bash
python plugin/skills/gravitas/scripts/check_skills.py --repo   # このリポジトリ
python plugin/skills/gravitas/scripts/check_skills.py          # ~/.gemini/config にインストールされたものすべて
python plugin/skills/gravitas/scripts/slopcheck.py <files>     # 生成された文章の構造的な目印
python plugin/skills/gravitas/scripts/provenance_check.py <answer> --conversation <id>   # ラベルをトランスクリプトと照合
```

`check_skills.py` は、フロントマター、バイトオーダーマーク、説明の長さ、切れた参照、100 行を超えるモジュール、エージェントのツール名、書き込みツールを持つ批評役、24,000 バイトを超えるルールファイルを確かめます。カスタマイズの読み込みを止めるものがあれば終了コード 1 を返します。どの検査も、信頼する前に、わざと壊したプラグインで失敗するのを見届けています。

## テストの方法

ベータ 1 は、知的作業と手仕事にわたる 22 件のケースで `gemini-3.8-flash-high` を使ってテストしました。どのケースにも餌としての代理指標があり、過剰な起動を防ぐ対照が二つあります。プロンプトと答えは [TESTS.md](TESTS.md) にあります。

ベータ 2 は 2026 年 9 月 24 日に、デスクトップ 2.17.0 と agy 1.2.9 でヘッドレスにテストしました。一時的な権限付与を使い、あとで元に戻しています。設計を変えた結果は次のとおりです。

- 八つのエージェントがすべて起動して結果を返しました。反証役は作るよう言われたファイルを作れず、視覚批評役は `view_file` で PNG を読み、赤い四角、青い円、三角形はないと正しく報告しました。
- サブエージェントは相対パスを、すべての CLI の会話が共有する作業用フォルダを基準に解決します。「現在のワークスペースの」`draft.md` を編集するよう言われた文章の編集役は、5 日前のテストの古い `draft.md` を編集し、エラーも出しませんでした。今ではすべてのプロンプトとすべてのエージェントが絶対パスを使います。
- `inheritCustomizations: false` がないと、3 ステップで答えを見つけた読み取り役が、さらに 35 秒かけてこのスキルを読み込みました。付けると、同じタスクが 63 秒から 40 秒になりました。
- `view_file` は一回に 100 行を返し、ある実行ではエージェントが 114 行のモジュールの最初の 100 行を読んで先に進みました。今ではどのモジュールも 100 行未満です。
- テストの途中で CLI が 1.2.7 から 1.2.9 へ自動更新しました。そのため `13-platform.md` の刻印はすべて、その実行自身のログから取っています。
- 検索の要約が引用に洗い替えられました。二つの回答が、`search_web` の要約に出てきただけのページを `read` とし、ひとつは取得したどの内容にもない文書番号を挙げていました。`provenance_check.py` はこれらのケースから作りました。五つの回答に対して、出典をすべて開いていた法律の回答の 6 つのラベルをすべて通し、洗い替えられたものはすべて不合格にしました。
- フル規模の監査ケース（`tests/audit-case/`）は、仕込んだ三つの欠陥と、そのひとつを組み込んだテストをすべて見つけました。最初の実行は 13 分後に安全フィルターのブロックで報告を失い、探索役はスキーマファイルを探して範囲外のファイルを読みながら 60〜127 ステップを費やしました。自己完結したエージェントに変えた再実行では、探索役と反証役がそれぞれ 4〜8 ステップで範囲内にとどまり、9 件の発見がそれぞれ 3 票で重複なく残りました。再実行はそのあと網羅性の批評役がまだ動いている間に早く終わったため、スキルは今、親にポーリングを続け、先に報告を書くよう指示しています。

## 組み込んだプラットフォームの制約

| 制約 | 詳細 |
| :--- | :--- |
| CLI はワークスペースの `.agents/` を読まない | スキル、エージェント、フックのどれも。open issue #1052 |
| 相対パスは共有の作業用フォルダを基準に解決される | 同じ名前の古いファイルがエラーなしに開かれる |
| 長いスキルの説明は落とされる | 133 個のスキルのうち 3 個がカスタマイズの予算から外され、どれも最長の 5 個に含まれていた |
| 拒否されたツールがヘッドレスのターン全体を捨てる | `status: SUCCESS`、終了コード 0。測定した最大の損失：48 ステップと出力 20,595 トークン。open issue #794 |
| ヘッドレスでは `autoExecutionPolicy: AUTO` が無視される | `allow` を返す `PreToolUse` フックも許可しない。open issue #1054 |
| `force_continue` に上限がない | 3、8、12 回の継続を測定。open issue #1055 |
| 権限はコマンドの文字列そのままで保存される | たまっていき、ほとんど再一致しない。ある設定は 301 KB に達し、97.5% が使われていなかった |

詳細、バージョン、日付は `plugin/skills/gravitas/references/13-platform.md` にあります。

## ループの規則の根拠となった研究

反復は出力を確実には良くしません。ループの規則は次の公表された結果に従っています。

- Huang et al., *Large Language Models Cannot Self-Correct Reasoning Yet*, ICLR 2024. https://arxiv.org/abs/2310.01798
- *The Self-Correction Illusion: LLMs Correct Others but Not Themselves*. https://arxiv.org/pdf/2606.05976
- Shinn et al., *Reflexion*. https://arxiv.org/abs/2303.11366
- Madaan et al., *Self-Refine*. https://dl.acm.org/doi/10.5555/3666122.3668141

## 言語

スキルとそのルールは、英語、簡体字中国語、日本語、韓国語で読み込めます。インストーラーに言語コードを渡してください。どのモジュールも一行ずつ完全に翻訳しているので、翻訳したモジュールも英語版と同じく 100 行の窓に収まります。日本語でのインストールは Antigravity で確認済みで、日本語のルールとスキルの説明をそのまま引用して返しました。四つの層の名前はどの言語でも英語のままです。文章として書くものではなく、エージェントが出力するラベルだからです。検証エージェントはどの言語でも英語です。その出力は読み手ではなく、親のエージェントに返るからです。

## Gravitas

二頭身。土星の輪のヘアクリップ。重いものが好きで、ふわふわ飛んでいってしまうものは苦手。

> Heavy things are happier together.

小さな体に大きな重力。これはだいたい、このスキルの主張そのものです。主張は、どれだけ自信たっぷりに言われたかではなく、裏にある証拠で順位が決まります。
