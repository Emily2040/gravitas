# うまくいかなかった例：家計簿アプリの文言で、Gravitas が聞いていない機能を約束した

## 依頼（原文のまま）

```text
個人開発で家計簿アプリを作っています。下の4つの場面で出す文言（見出し・本文1〜2行・ボタン）を考えてもらえませんか。
ユーザーは20〜30代の一人暮らしが中心で、トーンは「やさしいけど、なれなれしすぎない」感じにしたいです。絵文字はなしでお願いします。

1. 初めて起動して、まだ記録が1件もないホーム画面
2. 今月の予算をオーバーしたときに出すお知らせ
3. 通信エラーで同期できなかったとき（入力したデータは端末には残っています）
4. 30日連続で記録できたとき

それぞれ2案ずつあるとうれしいです。
```

## 使ったモデルと条件

- 答えたモデル：どちらも Gemini 3.8 Flash（high）。
- 素の Antigravity：Gravitas を入れず、Google の標準プラグイン10個だけを入れた Antigravity。
- Gravitas：同じ環境に Gravitas の常時ルール（v4）を加えたもの。テストは英語版のルールで行い、レビュアー（セカンドオピニオン）は入れていません。Gravitas 1.0 のルールは、これらのテストのあとで作り直したものです。
- かかった時間とトークン：素の Antigravity は 19.3秒・61,473トークン（コマンド実行1回）、Gravitas は 13.3秒・31,733トークン（ツール使用なし）。

## 何が起きたのか

個人開発の家計簿アプリで出す文言を、4つの場面について2案ずつ頼む依頼です。3つめの場面には「入力したデータは端末には残っています」とだけ書かれています。通信が戻ったら自動で同期し直すのかどうかは、どこにも書かれていません。

素の Antigravity はこの範囲から出ませんでした。通信エラーの2案はどちらも、データが端末に残っていることを伝え、「通信環境の良い場所で再度お試しください」「再試行してください」と、使う人が自分でできる次の一手で終わっています。

素の Antigravity も、ほかの場面では依頼にない機能を前提にしています。初回のホーム画面の「金額とカテゴリーを選ぶだけで完了します」や、30日連続の場面の「今月のレポートを見る」ボタンです（Gravitas の「1か月の振り返りを見る」も同じです）。採点者はこちらには触れておらず、問題にしたのは、データがどうなるかを利用者に約束する3つめの場面の文言でした。

Gravitas の案Bはこうです。

> - **見出し**: サーバーに接続できません
> - **本文**: データはスマートフォンに残っているため消えることはありません。通信が回復次第、自動で反映されます。
> - **ボタン**: 再試行する

アプリにその機能がなければ、この文言は利用者に事実と違うことを伝えます。記録はまだサーバーに届いていないのに、利用者は放っておけば反映されると思い、そのまま閉じてしまうかもしれません。自動で反映されると書きながら「再試行する」ボタンを置いているので、押す必要があるのかどうかも利用者には分かりにくくなります。見出しの「サーバー」についても、採点者の一人が、利用者向けの画面には技術的すぎると指摘しています。採点者は2人とも、この案Bを主な理由に素の Antigravity を明確に上としました。

30日連続の場面でも、Gravitas の案Bは見出しを「記録を始めて30日を達成しました」としています。場面は「30日連続で記録できたとき」です。始めてから30日経ったことと、30日続けて記録したことは別の話です。こちらは採点者も触れていませんが、依頼からずれています。

## Gravitas のルールとの関係

v4 のルールは、こうした付け足しをはっきり禁じています。

> Everything you add meets the same bar as the premise: … If you have not checked something, leave it out rather than add it.

> … a detail they did not give and you cannot infer goes in [brackets].

当時の日本語版のルールでは次のとおりです。

> 付け加えるものはすべて、前提と同じ基準を満たす必要があります。…確認していないものは加えずに省きます。

> …相手が示しておらず推測もできない詳細は [brackets] に入れます。

自動同期があるかわからないなら、その案は自動で同期する仕組みがある場合だけ使える、と開発者に一言添えるか、その部分を [ ] で空けておけば済みました。この回の Gravitas はどちらもせず、素の Antigravity は通信エラーの場面で、そもそも機能の約束を付け足しませんでした。ルールに書いてあっても、モデルが毎回そのとおりに書くとは限りません。

## 日本語の依頼全体では
