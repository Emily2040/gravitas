# 模块 15 - 线束探测

## 目的

本模块讲的是：在工作进行中，怎样改进模型周围的"线束"（harness），也就是决定 agent 做什么的那套东西：简报、门槛、检查单、工具规则、模型搭配、交接文件。在 `standard` 及以上规模，从第二轮起每轮开始前加载；只要一份简报或一道门槛有两种都说得通的写法，也要加载。模型权重是固定的，线束才是你能改的部分，一次长时间运行里的大部分质量就来自这里。

这个插件里每一条改变过结果的规则（门槛要有上下两界、先确认主体在画面里再测量、检查必须是一次工具事件、绝不终止不是你启动的进程、编辑按有界的块进行）都是在一次失败之后才找到的。探测则在失败之前找到下一条，代价是每轮多一个 agent。

## 方法

改编自 Google Research 的 Harness²（Apache-2.0；arXiv 2610.14224）：它在运行时分三步改进线束，并把学到的东西跨任务保存。论文报告，只走一步，三个工作基准上就提升 4.5 到 11.8 分。这里的改编版在 Antigravity 的扇出里运行。

1. **提出（Propose）。** 编排者为同一份简报写两个变体，两者只在一个维度上不同：测量的顺序、强调哪份参考、条目怎么拆分、由哪个模型或哪档思考强度来跑、一条工具规则、一道门槛的措辞。两个变体都在任何一个运行之前写下来。
2. **探测（Probe）。** 两个 agent 在同一条目上运行两个变体：同样的种子、输入、门槛、筛查器和评审。它们的输出和记录并排放在编号的 attempt 文件夹里。
3. **合成（Compose）。** 一个两次探测都没参与的 agent（导演，或名册里的一位评审）读两份结果，写出改进后的简报：采纳产生了更好结果的做法，并写明是什么证据做的决定：门槛数值、评审的原话、尝试次数。下一轮里，同类的每个条目都改用这份新简报。

要探测的条目，是上一轮失败最重的那一条，或者简报改动最大的那一条。默认每轮一对；要更多对，是预算决定，要写进报告。

## 没有标准答案时怎么判

一个场景、一章书、一个设计，没有答案卷。比较的是同一线束家族的两次运行在同样检查下的表现，所以算数的是差异，不是分数。

- 数值门槛和盲评审都认同的差异是证据，采纳。
- 只有一方看到的差异是假设，下一轮再探测一次，之后才采纳。
- 只出现在 agent 自述里的差异什么都不是（`01-evidence.md`）：探测 agent 的报告只是主张，合成者要对照记录核实其中承重的部分。
- 两个变体都通过了全部门槛，只在评审的口味上有别，算平局；留下便宜的那个，并记下这次探测没有产出信号。

## 改进线束

经验持久保存在工作区根目录的一个文件 `HARNESS_LESSONS.md` 里，每轮的简报都把它包含进去，编排者在提出变体之前先读它。每次探测一条记录：

```yaml
id: L-012
date: 2026-10-20
item: 第三幕的车身            # 探测的对象
dimension: 拆分方式            # 变体唯一改变的那件事
variant_a: 手写的 28 个横截面
variant_b: 从三张正投影参考描出轮廓曲线，放样后细分
evidence: 三个视角的轮廓 IoU 0.83 对 0.91；平滑度门槛 9.4% 对 2.1%；评审只对 A 说了"一块板"
adopted: B                     # 或 tie（平局）
now_lives_in: docs/ROUND5_BRIEFS.md 的 vehicles 一节；scripts/measure-quality.mjs 的 ACT3_BODY_SMOOTHNESS 门槛
status: active                 # active | retired（附上后来推翻它的证据）
```

一条经验被后来的探测推翻时，标为 retired，不删除；推翻它的证据写进同一条记录。这个文件就是本插件"反思"一步的持久版：Argon 或任何模型学到的关于这个项目的怪癖，写在下一次运行最先读到的地方，而不是写在压缩时会丢掉的地方。

## 规模模式

- **串行**，默认：每轮一对探测，合成后的简报进入下一轮。代价：每轮多一个 agent。
- **并行**，预算允许时：一轮里 K 对探测放在 K 个条目上，一起合成。把 K 写进报告，并记住并发的 subagent 共享账户的模型容量（`13-platform.md`）。
- **关闭**：`quick` 规模下；以及简报没变、上一次结果通过了全部门槛和评审的条目。

## 护栏

- 每次探测只改一个维度。一对在三件事上不同的变体什么也教不了你。
- 同样的种子、输入、检查。探测要么是受控比较，要么就只是两次尝试。
- 合成者两次探测都没参与（`10-iteration.md`：模型在别的 agent 的输出里发现的问题，比在自己的输出里多）。
- 绝不拿门槛去迁就工作来探测。变体改的是简报；门槛在一轮里固定不变，否则测到的是投机取巧，不是质量（`05-acceptance.md`）。
- 连续两轮差异低于门槛的分辨率，这个条目的探测就干了；停下来，并写明。
- 每次探测、它的结果和成本都写进报告的 Coverage 一节，附上经验编号。

## 反模式

- 失败之后凭记忆改写简报，没有受控的一对比较，却把改写叫做经验。
- 让写出变体 B 的那个 agent 来评判这一对。
- 凭自述采纳（"B 感觉更干净"），而不是凭门槛和盲评审。
- 因为 agent 便宜就一次探测很多维度。
- 把经验留在对话里，下一次压缩或下一次运行就丢了。
