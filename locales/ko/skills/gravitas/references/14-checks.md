# 모듈 14 - 언어 검사

## 목적

세어 봐야 맞는지 아는 형식이 있습니다. 절구의 평측, 하이쿠의 모라 수, 시조의 음절 수, 1.5 crore를 '만' 단위로 고쳐 쓸 때의 자릿수가 그렇습니다. 모델은 이런 것을 잘못 세고도 확신에 찬 말투로 씁니다. `scripts/checks/`에 있는 스크립트 6개가 이 세는 일을 맡습니다. Python 3.8 이상만 있으면 되고, 쓰는 데이터도 스크립트와 함께 들어 있습니다.

실행할 때는 설치된 플러그인 안의 전체 경로 `<home>/.gemini/config/plugins/gravitas/skills/gravitas/scripts/checks/<스크립트 이름>`을 씁니다. 아래 예시는 경로를 줄여 적었습니다. 스크립트를 실행하려면 `run_command`가 필요한데, 헤드리스 실행은 기본 설정에서 이를 거부합니다(`13-platform.md`). 명령을 실행할 수 없으면 같은 규칙을 손으로 적용하고, 스크립트를 돌리지 못했다는 사실을 보고서의 조사 범위(coverage) 항목에 적어 둡니다.

## 언제 어떤 검사를 돌리는가

| 스크립트 | 돌리는 때 | 넘기는 것 |
| :--- | :--- | :--- |
| `pingze_check.py` | 절구나 율시를 짓거나 검토할 때 | 간체자로 쓴 시. 요청자가 중화신운을 지정했으면 `--scheme xinyun` |
| `couplet_check.py` | 대련, 춘련, 개업 대련을 짓거나 검토할 때 | 상련과 하련을 인수 두 개로. 횡비는 `--hengpi`, 꼭 넣어야 할 글자는 `--require` |
| `mora_count.py` | 하이쿠, 단카, 센류를 짓거나 검토할 때 | 각 구의 가나 읽기. 검사용으로만 따로 씀 |
| `sijo_check.py` | 평시조를 짓거나 검토할 때 | 세 장. 검사용 사본에서 음보마다 `\|`로 구분 |
| `num_units.py` | 금액을 만, 억, 조, 万, 亿, 億, lakh, crore, million 사이에서 바꿀 때, 인민폐 금액을 갖은자(大写)로 쓰거나 공문서 금액을 쓸 때 | 단위가 붙은 숫자. `4.8万`, `1.5 crore` 등 |
| `locale_dates.py` | 한국어, 중국어, 일본어 독자에게 날짜를 쓸 때, 일본 연호(和暦)로 날짜를 쓸 때 | `show`에는 ISO 형식 날짜, `lint`에는 언어와 본문 |

```bash
python scripts/checks/pingze_check.py "秦时明月汉时关，万里长征人未还。但使龙城飞将在，不教胡马度阴山。"
python scripts/checks/couplet_check.py 知味停车香满座 闻香下马客盈门 --hengpi 宾至如归 --require 知味
python scripts/checks/mora_count.py haiku ふるいけや かわずとびこむ みずのおと
python scripts/checks/sijo_check.py "이 몸이|죽고 죽어|일백 번|고쳐 죽어" "백골이|진토되어|넋이라도|있고 없고" "임 향한|일편단심이야|가실 줄이|있으랴"
python scripts/checks/num_units.py same "1.5 crore" "1500万" "15,000,000"
python scripts/checks/locale_dates.py lint ko "퇴사일(2026.9.30)로부터 14일"
```

모든 스크립트가 `--json`(원장에 기록할 때)과 `--help`를 지원합니다. 출력은 영어로 나오고, 규칙 이름은 원어 그대로 씁니다. 二四分明, 孤平, 字余り, 종장 같은 식입니다.

## 출력 읽는 법

첫 줄이 판정이고, 그대로 인용해도 됩니다. `PASS`, `FAIL`, `ERROR` 중 하나입니다. `FAIL` 아래 `- `로 시작하는 줄은 어느 구, 어느 자리, 어느 값이 어떤 규칙에 어긋나는지 알려 줍니다. `note:`로 시작하는 줄은 판정을 떨어뜨리지 않습니다. 스크립트가 판단하지 못한 부분을 알려 줄 뿐입니다.

| 종료 코드 | 판정 | 할 일 |
| :--- | :--- | :--- |
| 0 | `PASS` | note를 읽고 그대로 씀 |
| 1 | `FAIL` | 짚어 준 문제를 하나씩 고치고 다시 돌려, 통과할 때까지 반복. 남겨 두는 문제가 의도한 것이라면 이유를 댈 수 있어야 함 |
| 2 | `ERROR` | 고칠 것은 입력. 모라를 셀 읽기에 한자가 남았거나, 음보에 로마자가 섞였거나, 숫자나 날짜를 스크립트가 읽지 못한 경우 |

결과에는 `executed` 표시를 붙이고 실제로 실행한 명령을 함께 적습니다(`01-evidence.md`). `num_units.py`의 `parse`, `show`, `daxie`, `ko-amount`와 `locale_dates.py`의 `show`는 변환만 합니다. 각 형식을 출력하고 종료 코드 0으로 끝납니다.

## 판정이 다루는 범위

한시는 한 번에 운서 하나로만 판정합니다. `pingshui`(평수운, 기본값)는 国, 白, 一, 十 같은 입성 글자를 측으로 봅니다. `xinyun`(중화신운)은 현대 표준 중국어 발음을 따르므로 이 글자들이 평이 됩니다. 그래서 평수운에 맞춰 지은 시를 중화신운으로 검사하면 구 안의 평측에서 걸릴 수 있습니다. 반대로 窗과 霜은 중화신운에서는 같은 운이지만 평수운에서는 다른 운목입니다. 요청자가 원한 운서로 검사하고, 그 시가 어느 운서를 따랐는지 답변에서 한마디 밝힙니다.

`pingze_check.py`가 보는 것은 구의 수, 이사분명(二四分明)과 사육분명(四六分明), 점(粘)과 대(对), 운자가 평성 운목 하나에 모이는지, 운을 달지 않는 구가 측으로 끝나는지, 삼평미(三平尾), 고평(孤平)입니다. 요구(拗救)는 다루지 않습니다. 그래서 평측을 일부러 어기고(拗) 다른 자리에서 메운(救) 구도 문제로 보고하고, note에 그 사실을 적습니다. 평과 측 두 가지 읽기를 가진 글자는 어느 쪽으로도 셉니다. 표에 없는 글자도 어느 쪽으로도 세므로, 그 글자 때문에 시가 실패하지는 않습니다. 스크립트는 그런 글자를 note에 적고, 어느 규칙이 그 글자에 기대면 출력 첫 줄의 `PASS` 뒤에 확인하지 못한 글자로 밝힙니다. 그 글자의 평측은 직접 따져 보고, note를 없애려고 글자를 바꾸는 일은 절대 하지 않습니다. 대개 번체자 때문이니 검사용 사본은 간체자로 씁니다. 다만 표에는 고전 이체자도 일부 들어 있어서(翦과 谿는 있고 剪과 溪는 없음), 간체자로 써도 note가 늘 사라지지는 않습니다.

`couplet_check.py`는 평측이 맞서는지를 2, 4, 6번째 글자에서만 봅니다. 너그러운 쪽의 해석입니다. 기본값 `--scheme both`에서는 두 운서 모두에서 어긋날 때만 문제로 보고하고, 한쪽에서만 어긋나면 note로 남깁니다. 긴 대련의 7번째 글자부터는 보지 않습니다. 두 구의 같은 자리에 같은 글자가 오는 동위중자(同位重字)도 실패로 봅니다. 다만 之, 而, 不 같은 허사(虚词)라면 note로만 남기고, 그 밖의 불규칙 중자(不规则重字)도 note로 남깁니다. 知味停车香满座 / 闻香下马客盈门에서 자리를 달리해 두 번 나오는 香이 그런 예입니다. 일부러 넣었거나 요청받은 동위중자는 이유를 밝히면 그대로 둘 수 있습니다. 글자가 표에 없어서 어느 운서로도 판정하지 못한 규칙이 있으면, `PASS` 줄에 그 글자를 밝힙니다.

`mora_count.py`는 넘겨받은 읽기를 셉니다. 한자를 어떻게 읽을지는 쓰는 사람의 판단이므로, 읽기가 틀리면 센 수도 틀립니다. `FAIL`은 글자 넘침(字余り)이나 글자 모자람(字足らず)을 뜻합니다. 의도한 파격(破調)이 아니라면 고칩니다. 계절어(季語)와 끊는 말(切れ字)은 판정하지 않습니다.

`sijo_check.py`는 표시해 준 음보마다 음절을 셉니다. 음보를 어디서 나누느냐부터가 시를 읽는 하나의 방식입니다. 문제로 보는 것은 장과 음보의 수, 종장의 두 규칙뿐입니다. 3·4·4·4에서 크게 벗어나거나 합계가 43~47을 벗어나는 것은 note로만 남깁니다.

`num_units.py same`은 직접 쓴 환산을 확인하는 용도입니다. 모든 식의 값이 같을 때만 통과합니다. `4万8`처럼 단위 뒤에 숫자 하나만 붙은 표기는 48,000으로 읽고, 구어체 표기라고 알려 줍니다. 零 뒤의 숫자는 적힌 자리 그대로 읽습니다(`4万零8`은 40,008). 亿, 億, 억, 兆, 조 뒤에 万이나 만 없이 千이나 百으로 끝나는 꼬리가 붙으면(`3억 5천`) 말할 때의 뜻대로 350,000,000으로 읽고, 적힌 대로 읽은 값을 함께 알려 줍니다. 그 꼬리 앞에 零이 있으면 적힌 대로 읽습니다. `daxie`는 원 단위 정수만 다룹니다. `ranges`는 ～나 대시, 至, 到로 이은 범위에 GB/T 15835를 적용해, 13～17万이나 15到30%가 아니라 13万～17万, 15%到30%처럼 양쪽에 단위를 붙여 쓰게 합니다.

`locale_dates.py lint`가 아는 형태는 몇 가지뿐입니다. 한국어에서는 마침표로 구분한 날짜의 마지막 마침표가 빠졌거나, 월이나 일 앞에 0을 붙였거나, 연도나 월 뒤의 마침표 다음을 띄어 쓰지 않은 경우입니다. 일본어에서는 연호의 연도가 옆에 적은 서기 연도와 맞지 않는 경우, 산문이라면 元年으로 쓸 연호 첫해를 1年으로 쓴 경우, 그 연호의 기간 밖 날짜를 그 연호로 쓴 경우(平成元年1月5日은 아직 昭和 연간), 元旦 앞에 1月1日을 쓴 경우입니다. 중국어에서는 두 자리 연도 뒤에 월이나 出生, 毕业, 入学, 入职가 오는 경우입니다. `PASS`는 이 형태들이 나오지 않았다는 뜻일 뿐입니다.

## PASS가 보여 주지 않는 것

여기 있는 검사는 모두 세는 일이라, 수가 맞아도 작품으로서는 실패할 수 있습니다(`05-acceptance.md`). 평측이 다 맞아도 밋밋하거나, 전고를 잘못 쓰거나, 요청과 어긋난 시는 얼마든지 있습니다. 정확히 환산한 숫자라도 애초에 환산할 숫자가 아니었을 수 있습니다. 스크립트가 통과한 뒤에도 독자의 자리에서 작품을 다시 읽으십시오.

## 데이터와 출처

`scripts/checks/data/pingshui.tsv`에는 평수운 106운이 들어 있습니다. 출처는 중국어 위키문헌의 '平水韻' 문서, 판 8264804의 간체자 표시입니다. 이 문서에는 PD-old(퍼블릭 도메인) 틀이 붙어 있고, 위키문헌 사이트 전체의 글은 CC BY-SA 4.0으로 제공됩니다. 파일 머리말에 두 가지를 모두 적어 두었습니다. `scripts/checks/data/mandarin.tsv`에는 현대 중국어 발음이 들어 있습니다. 출처는 pypinyin 0.55.0(MIT 라이선스, 허가 문구는 파일 머리말)이며, pypinyin이 첫 번째로 드는 발음이거나 그 단어 사전에서 3번 이상 쓰인 발음만 남겼습니다. 저장소 자체의 scripts 폴더에 있는 `build_check_data.py`로 두 파일을 다시 만들 수 있습니다.
