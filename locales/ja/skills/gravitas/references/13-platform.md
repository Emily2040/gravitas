# モジュール 13 - プラットフォーム

## 目的

このモジュールは、検証済みの Antigravity の振る舞いのうち、違うと思い込むと作業を無駄にするものを記録します。タスクが、Antigravity によるカスタマイズの読み込み、サブエージェントの実行、権限の適用、ヘッドレス実行に依存するとき、そしてツール、フック、スキル、権限が予想外の動きをしたときに読み込みます。

プラットフォームの変化が速いので、どの項目にも確認したバージョンと日付を付けています。2026 年 9 月 18 日から 23 日の間に、デスクトップ 2.15.0、2.15.1、2.16.0、2.17.0 と CLI 1.2.7、1.2.8、1.2.9 がリリースされました。特に記載がなければ、2026 年 9 月 24 日に Windows 11、デスクトップ 2.17.0、agy CLI 1.2.9 で確認したものです。WinGet でインストールした CLI は、21 秒離れた二つのテスト実行の間に、何の告知もなく 1.2.7 から 1.2.9 へ自動更新しました。そのため、ここの刻印はすべて、その実行自身のログにある `version:` の行から取っています。項目に頼る前に、その刻印を `https://antigravity.google/changelog` の変更履歴と比べ、関係する部分が変わっていれば確認し直します。

## カスタマイズの読み込み元

| 場所 | スキル | エージェント | ルール | 証拠 |
| :--- | :--- | :--- | :--- | :--- |
| `~/.gemini/config/skills/`、`agents/`、`AGENTS.md` | 読み込まれる | 読み込まれ、`agy agents` に表示される | 読み込まれる | 観察済み |
| `~/.gemini/config/plugins/<name>/` | 読み込まれる | 読み込まれるが `agy agents` には表示されない | `rules/AGENTS.md` から読み込まれる | テスト用プラグインで観察：モデルがスキルとエージェントの名前を挙げ、ルールに従った |
| `<repo>/.agents/` | `--add-dir` 経由でのみ読み込まれる | `--add-dir` 経由でのみ読み込まれる | `rules/` はどちらでも読み込まれない | 観察済み。open issue #1036、#1052 |

Gravitas がプラグインとしてインストールされるのはこのためです。ひとつのフォルダがスキル、検証エージェント、常時有効のルールを運び、`agy plugin disable gravitas` でそのすべてをまとめて止められます。`agy plugin list` はマーケットプレイスから取り込んだプラグインしか表示しないので、コピーしたプラグインは読み込まれていてもそこには出てきません。

ワークスペースの行はドキュメントと矛盾します。組み込みのカスタマイズガイドとスキルのページは `<repo>/.agents/` からの検出を説明し、IDE のガイドは IDE がそのフォルダを "automatically discovers and respects" と書いています。CLI では、リポジトリを `--add-dir` で渡すと、`.agents/` のスキル、エージェント、フックが読み込まれました。そのリポジトリが作業ディレクトリでもある場合も同じです。このフラグなしでリポジトリ内から起動すると、どれも読み込まれませんでした。ログの `workspaceDirs` はそのフォルダを示し、ログは `loaded 0 named hooks` と報告していました。`.agents/rules/` のルールはどちらの場合も読み込まれませんでした。リポジトリ自身のカスタマイズが必要なときは `agy -p "..." --add-dir <repo>` で実行します。デスクトップアプリと IDE は検証していません。

## カスタマイズを落とす予算

スキルの名前と説明はカスタマイズの予算を共有し、収まらないスキルは落とされます。133 個のスキルを入れた状態で、モデルはそのうち 3 個を "Excluded Skills (due to context budget limits)" の下に挙げました。3 個とも、インストール済みで説明の長い上位 5 個に含まれ、長さは 1,001〜1,028 文字でした。長さと除外の関係は、一度の観察からの推測です。説明は短く保ちます。このスキルの説明は 500 文字未満です。

ルールには 20,000 トークンの専用の予算があり、各ルールファイルは 24,000 バイトで行の境界に沿って切られます。予算を超えたルールはファイルへのポインターに格下げされます（read：組み込みの `agy-customizations` ガイドの `docs/rules.md`、CLI 1.2.7 の変更履歴）。

## 壊れたスキルは黙って失敗する

解析できない `SKILL.md` は読み飛ばされます。エラーは `~/.gemini/antigravity-cli/log/cli-*.log` に `skills.go:201] Failed to parse skill file ...` として書かれるだけで、ユーザーの目に触れる場所には出ません。UTF-8 のバイトオーダーマークひとつでこれが起き、Windows PowerShell 5.1 の `Set-Content` と `Out-File` は既定でそれを付けます。壊れたスキルがひとつあっても、他のスキルの読み込みは止まりません。

編集のたびに `scripts/check_skills.py` を走らせます。フロントマターの解析、説明の有無と長さ、バイトオーダーマーク、切れた参照、100 行を超えるモジュール、エージェントのツール名、書き込みツールを持つ批評役、ルールファイルの大きさを確かめます。

## サブエージェント

モデルが受け取るツール宣言は形が変わりました。`invoke_subagent` は `TypeName`、`Role`、`Prompt`、`Model`、`Workspace` を持つ項目の `Subagents` 配列を受け取り、`define_subagent` は `enable_write_tools`、`enable_mcp_tools`、`enable_subagent_tools` のフラグを受け取り、`manage_subagents` は一覧と停止を行います。詳細は `07-subagents.md` にあります。

カスタムサブエージェントのドキュメントによれば、`tools` リストに未対応のツール名を持つカスタムエージェントは停止するおそれがあります。CLI 1.2.7 以降、`find_by_name`、`grep_search`、`list_dir` は既定のツールセットになく、それらを挙げたエージェントだけが使えます。

並行するサブエージェントはアカウントのモデル容量を共有します。ほかの二つの実行が動いている間に、ある親の実行が、三つのサブエージェントが終わったあとで `RESOURCE_EXHAUSTED (code 429)` により `ERROR` の状態で終わりました。ファンアウトの規模はこれを考えて決めます。エージェントファイルが `inheritCustomizations: false` にしない限り、カスタマイズはサブエージェントに届きます。計測は `08-delegation.md` にあります。

## ヘッドレス実行

| 振る舞い | 証拠 |
| :--- | :--- |
| CLI の方針は `~/.gemini/antigravity-cli/settings.json` の `toolPermission`（既定は `request-review`）から来るので、デスクトップ設定の `autoExecutionPolicy: AUTO` は `agy -p` では効かない。`toolPermission: "always-proceed"` はヘッドレスで権限のないコマンドを実行し、`deny` のルールは引き続き守る | 1.2.9 で観察。issue #1054 |

| `decision: "allow"` と一緒に返した `overwrite` は適用されてエージェントに告知され、権限は書き換え後の引数で確認される。`decision` のない `overwrite` は拒否になる | 2026 年 9 月 19 日と 24 日に観察 |

| ツールが拒否されるとそのターンは捨てられ、実行は `"status": "SUCCESS"` と終了コード 0 を報告する。測定した最大の損失は完了済み 48 ステップと出力 20,595 トークン | 1.2.7 で観察し、1.2.9 でも再び観察。open issue #794 |
| ヘッドレス実行から起動したサブエージェントは、`read_file` を許可しない限り、ワークスペースのファイルの読み取りを拒否される | 1.2.9 で観察 |
| サブエージェントの実行中にターンを終えた親は、その結果を受け取らない。実行は子の終了を待ってから閉じ、ログに "Failed to wake idle agent on message: run state not found" を記録し、親の最後の返答で `SUCCESS` を報告する | 1.2.9 で、制御した 2 回の実行の 2 回と監査 1 回で観察。issue #1044。ポーリングを続けた実行は最長 338 秒待ち、すべての結果を受け取った |

| `--json-schema` は、読めるファイルでも JSON オブジェクトでもない引数を文字列のスキーマに変え、ルートがオブジェクトでないスキーマは常に HTTP 400 を返す | 1.2.7 で 42 回の実行により観察し、1.2.9 でも再び観察。open issue #1064 |

あるセキュリティ監査は、13 分と 7 つのサブエージェントのあと、最終的な返答が "This request was blocked by Gemini's filters. They can occasionally trigger by mistake on safe coding, security, or biology-related queries." に置き換えられました（1.2.9 で `gemini-3.8-flash-high` により観察）。ヘッドレス実行は明示的な権限か `toolPermission` を前提に計画します。フックの許可は頼りにならず、`SUCCESS` の状態はそのターンの作業が残ったことの証拠ではありません。

## フック

- `invocationNum` はゼロから数えるので、最初のターンは 0 を報告します。ドキュメントの例は 3 を示しており、そのことを書いていません。
- `hooks.json` のコマンドでは何も引用符で囲まないでください。Windows では引用符がそのままプログラムに渡ります。引用符で囲んだ実行ファイルは "not recognized" となり、引用符で囲んだスクリプトのパスはフックのフォルダの後ろに連結されます（issue #222）。空白を含まないパスを引用符なしで使います。
- `hooks.json` は JSON のシリアライザーで書きます。bash のヒアドキュメントは Windows パスの二重のバックスラッシュをひとつにまとめ、不正なエスケープを生みます。
- フックの作業ディレクトリは `hooks.json` のあるフォルダです。
- 失敗した `PreInvocation` フックは飛ばされます。不正な JSON、空の出力、0 以外の終了、タイムアウトはいずれも許容されました（2026 年 9 月 19 日）。`PreToolUse` フックは失敗すると拒否します。不正な JSON、`{}`、`decision` の欠落、0 以外の終了はどれも呼び出しを拒否し、通すのは空の出力だけです（1.2.9）。タイムアウトは実際に効きます。デスクトップ 2.4.3 以降、実行できない設定は読み込み時にエラーで拒否されます。
- `terminationBehavior: "force_continue"` には上限がありません（open issue #1055）。1.2.9 ではフックが 12 回動き、さらに 11 回のモデル呼び出しを強制しました。そのうち 9 回は中身のない返答で、2 回は誰も頼んでいないツールを呼びました。`Stop` フックは `decision: "continue"` で終了を止めることができ、上限を設けるための `executionNum` を受け取ります。`10-iteration.md` を参照してください。

フックを確かめるには、スクリプトに見張り用ファイルへの追記をさせ、固有の値を注入して復唱するよう指示し、その両方を確認します。正しいファイルと静かなログは、フックが走った証拠ではありません。

## 権限

権限はコマンドの文字列そのままで保存され、ときには最初の語だけになるので、`command(if)` や `command(&)` といった項目が、ひとつの権限として丸ごと保存された数 KB のスクリプトと並びます。権限はバイト単位で同一のコマンドにしか再一致しないため、確認はまた出てきて、使われない権限がさらに追加されます。あるマシンの `~/.gemini/config/config.json` は 301 KB に達し、その 97.5% が使われない権限で、最長の項目は 36,331 文字でした。ときどき大きさを確かめます。役に立つのはドメインに対する `read_url` の権限です。

プロジェクトの設定はグローバルの設定より優先されます。`~/.gemini/config/projects/*.json` の各ファイルは独自の実行方針を持つことができ、プロジェクトが別の値を持つ間は、画面でグローバルの設定を変えても効きません。方針の値は `always-proceed`、`request-review`、`strict`、`proceed-in-sandbox` で、Windows ではデスクトップ 2.15.1 以降、ファイルとネットワークのサンドボックスが使えます（read：組み込みの `antigravity-guide` スキル、その `app.md` のリファレンス、変更履歴）。

CLI は、自身の `settings.json` の `permissions.allow` と、`~/.gemini/config/config.json` の `globalPermissionGrants.allow` の両方から権限を読みます。後者はログの `stored shared config permissions` の行で確認できます。Windows では、`command()` のルールが一致するのは、完全に同じコマンド行、`command(*)`、または行全体を覆う `regex:` のルール（例：`command(regex:git .*)`）だけです。`command(git)` と `command(git *)` は、引数のある呼び出しのどれにも一致しません（1.2.9 で観察。issue #619、#955）。

モデルに決して権限を求めるなと命じるルールは機能しません。方針はモデルに相談される前に適用されるからです。

## 環境ごとのツール

agy 1.2.9 の既定のエージェントのツール一覧には、`ask_question`、`call_mcp_tool`、`define_subagent`、`generate_image`、`invoke_subagent`、`list_resources`、`manage_subagents`、`manage_task`、`read_resource`、`read_url_content`、`replace_file_content`、`run_command`、`schedule`、`search_web`、`send_message`、`view_file`、`write_to_file` と、有効な MCP サーバーのツールがありました。ブラウザツールはありませんでした。ブラウザツールはデスクトップアプリでブラウザ連携が有効なときに現れますが、記録されたデスクトップでの実行のひとつにはまったくなかったので、計画の前に確認します。代わりの方法は `04-runtime-verification.md` にあります。

知っておく価値のある機能：`ask_question` は対話セッションでユーザーに構造化された質問をします。`/plan` は作る前に編集できる計画を下書きし、Plan Review Policy の設定に従います（デスクトップ 2.17.0）。`agy --effort low|medium|high` は推論の強さを設定します。`agy models` はアカウントで使えるモデルを一覧します。`agy --agent <name>` はカスタムエージェントとしてセッションを始めます。

## スクリプトによる編成

ファンアウトを数百の項目に対して正確な数え上げで走らせる必要があるときは、どのエージェントの記憶よりもスクリプトのほうが確実です。SDK プラグインのドキュメント（バージョン 0.0.7）によれば、Google Antigravity Python SDK（`pip install google-antigravity`）は、`SubagentConfig`、`enabled_tools`、`allowed_subagents`、`max_subagent_depth`、構造化出力のための `response_schema` を使って、コードからエージェントとサブエージェントを起動します。認証には `GEMINI_API_KEY` を使い、料金は Antigravity のプランではなくそのキーに請求されます。この経路はこのスキルとはまだ試していないので、記載はあるが未検証のものとして扱います。

## 動いているプラットフォームで確かめる

上の項目のいくつかはドキュメントと矛盾し、しかもそれを確かめたテストの最中に CLI が自動更新しました。プラットフォームの振る舞いがタスクにとって重要なら、インストールされたバージョンで試し、結果に刻印を押します。証拠の層は、作業に当てはまるのと同じようにプラットフォームにも当てはまります。
