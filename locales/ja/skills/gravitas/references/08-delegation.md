# モジュール 08 - 委任

## 目的

このモジュールは、結果を確かめられるようにサブエージェントへ指示を出す方法と、その主張が報告に入る前に実際に何をしたかを確かめる方法を扱います。`07-subagents.md` と一緒に読み込みます。

## 役割の取り決め

使えない出力を生む指示は、トークンを消費したうえでやり直しが必要なものを生みます。すべての `Prompt` に六つのことを書きます。

1. 範囲：対象となるファイル、主張、ルート、出典を絶対パスか完全な URL で書き、それ以外は含めません。範囲が重なれば重複が生じ、範囲の隙間は黙った見落としを生みます。
2. 問い：答えを確かめられるほど狭い、ひとつの問い。
3. 返す形：`schemas/finding.schema.json` に合う発見レコード、または `schemas/verdict.schema.json` に合う判定ひとつ。何を探すかだけを伝えられたエージェントは作文を書きます。
4. 証拠：すべての主張が同じフィールドに層と出所を持ち、第 4 層のものは仮説と明記します。
5. 停止条件：範囲を網羅したとき、または指定した件数に達したとき。
6. 行き詰まったときの振る舞い：ツールが拒否されたりファイルがなかったりしたら、あるものを `blocked` の状態とエラーテキストとともに返します。拒否の回避は禁止で、プラットフォーム自身の拒否メッセージも同じことを言っています。

子は結果を返し、進捗を語りません。

サブエージェントには決して相対パスを渡しません。2026-09-24 の agy 1.2.9 では、`view_file` は相対パスをワークスペースではなく、すべての CLI の会話が共有する `~/.gemini/antigravity-cli/scratch/` を基準に解決しました。「現在のワークスペースの」`draft.md` を編集するよう言われた `gravitas-prose-editor` は、5 日前のテストがそのフォルダに残した別の `draft.md` を編集し、エラーもなく結果を返しました。`gravitas-refuter` と `gravitas-visual-critic` も同じフォルダに行き当たり、何も見つけられずに `blocked` を返しました。こちらのほうがましな失敗です。

すべての子に、必要なものはすべてプロンプトと指示に入っていると伝えます。監査のテストでは、出力が「the Gravitas finding schema」に合っていなければならないと言われた探索役が、127 ステップの大半をそのファイルを求めてユーザーのフォルダを探すことに費やし、途中で git の内部ファイルや無関係なテストの出力を読みました。同梱のエージェントは今ではスキーマ全体を例として持ち、探すべきものはないと伝えられています。再実行では、すべての探索役と反証役が 4〜8 ステップで終わり、範囲外のものを何も開きませんでした。

パストラバーサル、インジェクション、データ流出を証明する検証役は、一時フォルダに自分で作った無害なカナリアを標的にします。同じテストで検証役は、欠陥のある関数を通じて `C:\Windows\win.ini` を読むことでトラバーサルを証明しました。そこでは無害でしたが、本物の秘密を持つマシンでは誤った習慣です。

```text
Role: Refuter, session handling
Territory: the claim below and C:/work/app/src/auth/session.ts. Nothing else.
Claim: "logout() leaves the refresh token valid" (C:/work/app/src/auth/session.ts:88-120)
Question: can you show this claim is false?
Return: one JSON object matching schemas/verdict.schema.json.
Evidence: every statement carries its tier and source, e.g. read (src/auth/session.ts:97, "...").
Stop: after one verdict.
If a tool is denied, return status "blocked" with the error text.
```

## 委任の完全性

親自身の状態は子について何も語らないので、統合の前に子をひとつずつ確かめます。

1. すべての子を、会話 ID と最終状態（`done`、`failed`、`denied`、`empty`、`killed`）とともに台帳に記録します。
2. `manage_subagents` を `list` で呼び、まだ走っているものがないことを確かめ、上限を超えたものは `kill` します。ヘッドレス実行では、すべての子が終わるまでツール呼び出しを続けます。「批評役を待っています」のようなテキストの返答でターンを終えると実行全体が終わることがあり、その後に届いた結果は失われます。
3. 失敗した子、拒否された子、何も返さなかった子を、名前を挙げてカバレッジの欠落として報告します。
4. 子が返した結論を支える主張ごとに、`logAbsoluteUri` にある子のトランスクリプトでラベルの裏のツールステップを確かめます。`scripts/provenance_check.py <child answer> --conversation <child id>` がすべてのラベルについて一度にこれを行います。規則は `02-evidence-traps.md` の「委任した主張」にあります。
5. それぞれの主張を、層と書き手を添えて報告に入れます：`read by gravitas-reader (...)`。

黙った失敗はこのプラットフォームで実際に起きています。2026-09-24 の agy 1.2.9 でのヘッドレス実行で、サブエージェントの最初の `read_file` が拒否されて何も生まれず、親は開始から 5.4 秒で `"status": "SUCCESS"` と "I am waiting for its response." を返して終わりました。権限を与えると、同じ種類の実行はサブエージェントを 63 秒待ち、その答えを報告しました。二度目の早期終了には拒否が絡んでいませんでした。フル規模の監査が `manage_subagents` で 1 分間ポーリングしたあと、"Waiting for the Completeness Critic subagent to complete its evaluation" でターンを終え、CLI は 29 秒後に実行を閉じました。批評役の結果が届いたとき、ログには "Failed to wake idle agent on message: run state not found" と記録されていました。

## 独立性

書き込める批評役は、誤診したものを修理し、成功を報告し、その修理が証拠の一部になります。ロスターの観察と判断の役割がどれも編集ツールを持たないのはそのためです。

成果物は「あなたの前回の試み」としてではなく、第三者の出力として批評役に渡します。モデルは他人の作業だと思うものの中の誤りをずっとよく見つけ、ラベルを付け替えるだけで検出が改善します。検証を、主張を生んだエージェントに戻してはいけません。

エージェントファイルで止めない限り、カスタマイズはサブエージェントに届きます。agy 1.2.9 で `gravitas-reader` は 3 ステップで答えを見つけ、そのあと 35 秒かけてこのスキルを読み込みました。プラグインの常時有効のルールがそう指示したからで、実行は 63 秒かかりました。エージェントファイルに `inheritCustomizations: false` を入れると、同じタスクは 40 秒で終わり、スキルのファイルはひとつも開かれませんでした。同梱のエージェントはすべてこれを設定しており、親のルールや枠組みを批評役のコンテキストから締め出す役割も果たします。どれもサブエージェント用のツールを持っていません。

## 並行する書き手

同じファイルを二つの書き手が書けば上書きし合います。作業をファイルで分けるか、書き手を順番に走らせるか、`Workspace: "branch"` または `Workspace: "share"` でそれぞれに隔離されたワークスペースを与えます。隔離モードはツール宣言に記載されていますが、このスキルではまだ試していません。どの場合も親を通じて統合します。

## アンチパターン

- 編集ツールを持つ批評役、または検証対象の作業を範囲に含む検証役。
- 主張を生んだエージェントによる検証。
- すべての専門役に `enable_subagent_tools` を付け、誰も監査できない深く遅いツリーを作ること。
- 返す形のない役割の指示。
- 結論が依拠する主張について、子の要約だけを読み、トランスクリプトを読まないこと。
- `manage_subagents` なら実行中の子を表示したはずの状況で、実行完了と報告すること。
