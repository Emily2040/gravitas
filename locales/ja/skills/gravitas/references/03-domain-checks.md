# モジュール 03 - 分野別の検証

## 目的

このモジュールは、各分野で何が独立した検証にあたるのか、そしてどの分野にも現れる代理指標の罠を扱います。主張がソフトウェアの外にあるとき、またはその主張を決着させる検証が明らかでないときに読み込みます。

## 代理指標の罠

本当の問いは確かめにくく、隣の問いは確かめやすいとき、確かめられるのは簡単なほうです。それが通り、作業は「検証済み」と報告されます。丁寧に見える仕事が間違う最もよくある形であり、検証が原理的には可能で実際には面倒な場面ならどこでも起こります。

| 本当に重要な問い | 実際に確かめられる代理指標 |
| :--- | :--- |
| このシーンはチョコレート工場に見えるか | キャリアが 10 台、ローラーが 6 本あるか |
| この契約は私が主張する義務を生じさせるか | 文書に *indemnify*（補償する）という語があるか |
| この証明は正しいか | すべての行の書式が整っているか |
| この物理の答えは正しいか | 単位が打ち消し合うか |
| この研究は主張を裏づけるか | 引用された論文は存在するか |
| この翻訳は忠実か | 出力は文法的に正しいか |
| この財務モデルは健全か | スプレッドシートがエラーなく計算されるか |
| この歴史の記述は正確か | 脚注があるか |
| スクリーンリーダーの利用者はこのページを使えるか | Lighthouse のアクセシビリティが 100 か |
| このプラットフォーム機能は動くか | ドキュメントに書いてあるか |

右の列の検証はどれも必要ですが、十分なものはひとつもありません。どれも左の性質が成り立たないまま通り得ます。だからこそ魅力的で、緑の結果で埋まった文書ができあがります。

ある検証が代理指標かどうかは、本当に気にしていることが偽のときにも通り得るかで判断します。通り得るなら、それを残したうえで、隣に本当の検証を加えます。

実測例：ある実行で、3D シーンにチョコレートのメッシュがちょうど 1 つあり、その UUID がすべてのアニメーション段階で保たれていることが確認されました。レンダリング画像を渡された独立した観察者は、チョコレートは存在しないと報告しました。メッシュが一度も見えていなかったからです。どちらの報告も正しいものでした。メッシュの数が可視性の代わりになり、その実行のどの検証もこのすり替えに気づきませんでした。

## 分野ごとの「観察」の意味

第 1 層とは対象そのものを見ることであり、何が「対象そのもの」かは分野によって変わります。変わらないのは、それが主張を生んだ推論から独立していなければならないという点です。ソフトウェアとレンダリング成果物は `04-runtime-verification.md` で扱います。

### 数学

証明を一行ずつ読むのは第 3 層です。第 1 層は、命題をランダムな点で数値評価すること、境界ケース（ゼロ、一、空、負、無限大）を試すこと、極限と漸近挙動を確かめること、独立した第二の方法で検証すること、反例を作ろうとすることです。閉じた式が一点でも数値評価と食い違えば、導出がどれほどきれいに読めても、その式は死んでいます。

### 物理と工学

まず次元解析から始めます。費用がかからず、誤りのかなりの割合を捕まえるからです。次に既知の量と桁を比べ、10 倍以内に収まることを期待します。次に極限のケースで、変数がゼロや無限大に向かうとき、式は既知の結果に帰着しなければなりません。次に保存則です。際限なく増えるエネルギー、`c` を超える速度、装置より長い長さは、導出を信用しなくても観察できます。

### 法律

実際に効力のある条文を取り出し、義務を生じさせる文言そのものを引用します。判決要旨や要約ではありません。その法的根拠が存在し、効力を持ち、覆されたり廃止されたり取って代わられたりしておらず、該当する日付に該当する法域で適用されることを確認します。判決理由（holding）と傍論（dicta）を区別します。実在の判例に解決される引用は、「引用がその主張どおりの内容を述べている」ことの代理指標にすぎません。

### 実証的・事実的な主張

要約ではなく一次資料にあたります。資料の数字が繰り返されている数字と同じであること、対象集団や範囲が主張と一致すること、より新しいものに取って代わられていないことを確かめます。二次資料を三つ経由した数字は、よくて第 3 層、しばしば引用をまとった第 4 層です。

### 統計とデータ

生の数値から計算し直します。合計を突き合わせます。効果が大きいと認める前に基準率と比べ、分母を確かめます。誤解を招く割合のほとんどは分母に潜んでいます。

### 医学と応用的なエビデンス

研究対象の集団が目の前のケースに似ているか、効果量が統計的に有意なだけでなく臨床的に意味があるか、知見が再現されているかを確かめます。単一の試験よりシステマティックレビューを、その試験についてのプレスリリースより試験そのものを優先します。用量、相互作用、適格性の答えは、体重、腎機能、服用中の薬といった入力に依存します。それらが欠けているときは、それらの関数として答えるか、答えないかのどちらかです。

### 金融と定量的な仕事

別の経路で計算し直します。財務諸表が整合することを確かめます。成長率を歴史と照らして妥当性を確認します。もっともらしい率を 30 年複利で回すモデルは、もっともらしくない数字を出し得るからです。年 7% で 30 年は 7.61 倍であり、3 倍ではありません。

### 翻訳

独立に逆翻訳し、二つの版がそれぞれ何を意味するかを比べます。専門用語、単位、日付、名前、数字がそのまま保たれているかを確かめます。文法的で流暢な出力は代理指標であり、忠実な出力こそが目標です。

### 手仕事：カラー、編集、執筆、デザイン

これらには唯一の正解がないため、ループの規則が異なり、代理指標の罠も形を変えます。どの手仕事にも検証可能な層と判断が必要な層があり、両者を混同すると、明らかにおかしいまま作品が出荷されます。

検証可能な層は実在し、しばしば客観的に違反を判定できます。放送規格内のレベルと色域、白飛びや黒つぶれ、色空間と伝達関数のタグ、冒頭だけでなく全尺にわたる音声同期、フレームレートの整合、アスペクト比、物語内の名前や事実の一貫性、仕様に対する文字数などです。これらは第 1 層と第 2 層です。測定してください。

判断が必要な層とは、作品が読めるか、響くか、主張しているものに見えるかです。どの指標もそこには届きません。グレーディングは規格内に収まっていても濁って見えることがあります。カットはすべての拍に合っていてもリズムがないことがあります。段落は能動態で副詞なしのまま字数を満たしても、何も言っていないことがあります。

検証可能な層は必要であり、だからこそそこを通ると検証したように感じます。判断が必要な層には、新しい批評役を二度使います。一度目は趣意書なしで、これは何として読めるか、何についてのものか、どんな気分をまとっているかを聞きます。二度目は趣意書つきで、意図を果たしているか、具体的にどこで及ばないかを聞きます。二度目だけを行うと、批評役は渡されたばかりの意図を追認しがちです。

好みの判断はよくて第 3 層、たいていは第 4 層です。ラベルをつけたうえで、それでも判断は示します。判断を拒むこと自体がひとつの失敗だからです。

### ウェブデザインとインターフェース

ここでは検証可能な層が際立って豊富です。コントラスト比、ターゲットサイズ、見出しの順序、代替テキストの有無、キーボードフォーカスの可視性、各ブレークポイントでのレイアウト、横スクロールがないことなどです。自動監査はこれらを報告してスコアを出し、そのスコアが代理指標です。自動ツールが捕まえられるのは WCAG 違反のおよそ三分の一で、数え方によっては件数ベースで約半分です。残りは判断を要します。見出しがその下の節を説明しているか、リンクテキストが文脈なしで意味をなすか、読む順序が見た目の順序と一致するか、エラーメッセージが何をすべきかを伝えているか。代替テキストがあることは測れますが、代替テキストが役に立つかは測れません。

ページは Lighthouse で 100 点を取っても、なお使えないことがあります。ページだけを渡され説明を一切受けていない閲覧者に、初めての訪問者が主要な操作を見つけられるか、階層が読み取れるか、インターフェースが信頼できそうに見えるかを確かめてもらいます。

### 歴史と解釈

その文書についての記述ではなく、文書そのものにあたります。来歴と日付を確定し、その記述が残ることで誰が得をしたかに注意します。この分野の多くは第 3 層にあり、誠実な報告はそう述べます。

## 新しい分野での二層の切り分け方

上の一覧は網羅的ではありません。建築、料理、音楽制作、教育、写真、UX リサーチも、同じ三つの問いで切り分けられます。

1. ここで機械が測れるものは何か。それが検証可能な層、第 1 層と第 2 層です。安くて必要なので、測定します。
2. 有能な判断者にしか決められないものは何か。それが判断が必要な層、第 3 層と第 4 層です。批評役が必要で、その結論は判断としてラベルを保ちます。
3. どの指標が検証のように感じられるか。始める前にその名前を挙げます。それはほぼ必ず、実在し、必要で、報告して満足できるものであり、だからこそ罠になります。

三つ目の問いに答えがないなら、その分野の検証は簡単で、代理指標の罠は当てはまりません。

何かを検証不能と宣言する前に、安価な検証手段がどんな形になるかを考えます。一回の数値評価、条文を一度取り出すこと、一回の桁の比較、一次資料を一度探すこと。どれも数分で済み、エージェントが本来なら長々と議論して間違った結論に至る問いを決着させます。数値評価は導出の優雅さを気にせず、条文は記憶の中の文言を気にしません。だから同じ原則が、コードから法律、物理まで、そのまま通用します。
